1. Overview
▼

This framework provides automated test coverage for two core features — Login and New Test Case — covering both UI interactions and API contracts.

It is built with Playwright and TypeScript, follows the Page Object Model pattern, and is designed to run fully offline with no external dependencies, no real backend, and no credentials required out of the box.

The suite covers positive and negative scenarios across both UI and API layers, matching the test cases defined in the project's Test Cases document (TC-001) and aligned with the framework rules defined in rules.md.

🏗

3. How It Runs Offline
▼

The framework requires no real application, no real backend, and no credentials to run. This is achieved through two layers:

Layer 1 — Local Mock App (port 4000)

  • Static HTML pages served by npx serve
  • Implements the exact form behaviour from the requirements
  • Frontend validation, error messages, redirects all work as in the real app
  • Started automatically by Playwright before tests run

Layer 2 — Mock API Server (port 4001)

  • Real Node.js HTTP server using no external libraries
  • Handles POST /login and POST /test-cases
  • Returns correct status codes: 200, 201, 400, 401
  • Also started automatically by Playwright before tests run
npm test
→
Playwright starts both servers
→

→
HTML + JUnit reports generated

When a real application is available, a .env file with BASE_URL and API_BASE_URL is all that is needed to switch — no code changes required.

4. Page Object Model
▼

Every page has a dedicated class that encapsulates all locators and actions. Spec files never interact with the DOM directly — they only call Page Object methods.

Page Objects

  • BasePage — shared navigate(), waitForNetworkIdle()
  • LoginPage — login(), fillEmail(), isErrorBannerVisible() etc.
  • NewTestCasePage — createTestCase(), fillSteps(), isTitleErrorVisible() etc.

Locator Priority (from rules.md)

  • ARIA role + name — first choice
  • Label text — form fields
  • Placeholder — fallback for inputs
  • data-testid — for error messages
  • CSS / XPath — last resort only, with comment
